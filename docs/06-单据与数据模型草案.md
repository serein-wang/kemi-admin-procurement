# 06 · 单据与数据模型草案

> 草案仅服务 Spec 评审与 MVP 估点；**不是**已定库表。字段可增删，主键策略随选型定。

## 1. 实体总览

```
User / Role
Company (SZ/HK) · Currency
Vendor（行政供应商，可后接主数据）
PR 请购单 ──< PRLine
RFQ / QuoteCompare 询价比价
PO 行政采购单 ──< POLine
GRN 收货验收 ──< GRNLine
InvoiceRegister 进项发票
MatchSheet 三单匹配
PREPAY 预付申请
PREPAY_SETTLE 核销
PAY 付款申请
AssetCard 资产卡
EXP 报销单
PRE 事前申请（路径②强制）
OverdueChase 超期跟催（①-E*）
```

## 2. 公共字段（建议）

所有单据头：`id`, `doc_no`, `company_code`, `currency`, `amount`, `status`, `applicant_id`, `created_at`, `updated_at`, `created_by`

金额：存最小币种单位或 decimal(18,2)；**同一单据币种不可变**。

## 3. 请购单 PR

| 字段 | 说明 |
|------|------|
| `dept_id` | 申请部门 |
| `purpose` | 事由 |
| `capex_hint` | 是否倾向固资（申请人勾选，最终 D4 以规则为准） |
| `budget_id` / `reserve_status` | 预算钩子（Q8） |
| `dept_approver_id` / `finance_approver_id` / `ceo_approver_id` | 实际审批人 |
| `rfq_required` / `rfq_waived` / `waive_reason` | D3 |
| `status` | 见 docs/02 |

PRLine：`item_name`, `spec`, `qty`, `est_unit_price`, `est_amount`, `category`（固资/耗材/服务…）

## 4. 比价 RFQ / QuoteCompare

| 字段 | 说明 |
|------|------|
| `pr_id` | 关联请购 |
| `vendor_quotes[]` | 至少 3 家（达门槛时）；`vendor_name`, `amount`, `lead_time`, `selected` |
| `selected_vendor_id` | 选定 |
| `comparer_id` | 行政专员 |

## 5. 行政采购单 PO

| 字段 | 说明 |
|------|------|
| `pr_id` | 来源请购 |
| `issuer_id` | 下单人（行政）→ S1 |
| `vendor_id` | 供应商 |
| `payment_terms` | `after_delivery` / `monthly` / `prepay` → D6 |
| `payment_terms_days` | 月结天数（可选） |
| `contract_no` / `attachments` | 合同等 |
| `status` | 见 docs/02 |

## 6. 收货 GRN

| 字段 | 说明 |
|------|------|
| `po_id` | |
| `accepter_id` | 验收人 → S1 |
| `proxy_receiver_id` | 代收登记人（可选，Q6） |
| `received_at` | |
| `result` | 合格/让步/拒收 |

## 7. 发票 InvoiceRegister · 三单匹配 MatchSheet

发票：`invoice_no`, `invoice_type`（形式/专票/普票…）, `amount`, `tax`, `po_id`, `formal_of`（形式→正式替换）

匹配：`po_id`, `grn_id`, `invoice_id`, `prepay_id?`, `match_result`, `matched_by`

预付场景：匹配内容含预付已付额核对（源稿 ①-10）。

## 8. 预付 PREPAY

| 字段 | 说明 |
|------|------|
| `po_id` | 必填 |
| `applicant_id` | 行政 = S5 申请人 |
| `amount` / `ratio` | 预付额与占 PO 比 |
| `attachments` | PO/合同/形式发票 |
| `payment_approver_id` / `payer_id` | S5 |
| `accrual_voucher_ref` | ①-P7 |
| `overdue_flag` / `promised_delivery_date` | 例外 |
| `status` | 见 docs/03 |

核销 PREPAY_SETTLE：`prepay_id`, `invoice_id`, `match_id`, `dp2_result`（equal/short/over）, `tail_pay_id?`, `refund_id?`

## 9. 付款 PAY

`source_type`：`po_balance` | `prepay` | `prepay_tail` | `expense`  
`finance_approver_id`, `payer_id`（出纳）, `paid_at`, `bank_ref`

## 10. 资产卡 AssetCard

`asset_no`, `name`, `po_id`/`grn_id`, `custodian_id`, `location`, `creator_id`（S4）, `capitalized_amount`, `status`

## 11. 报销 EXP · 事前 PRE

EXP：`pre_approval_id`（必填）, `invoice_nos[]`, `dept_approver_id`, `ticket_checker_id`, `finance_cosigner_id?`, `payer_id`, `employee_account`

PRE（强制）：`amount`, `purpose`, `status`；EXP 必填 `pre_approval_id` → 已批准 PRE

## 12. 状态枚举汇总（草案）

| 实体 | 枚举 |
|------|------|
| PR | draft, submitted, dept_approved, finance_approved, ceo_approved, sourcing, ready_for_po, closed_converted, rejected, cancelled |
| PO | draft, issued, awaiting_prepay, awaiting_receipt, partially_received, fully_received, matched, payment_pending, paid, closed, cancelled |
| GRN | draft, confirmed, rejected |
| PREPAY | draft, submitted, dept_approved, finance_cosigned, ceo_approved, finance_payment_approved, paid, accrued, awaiting_delivery, settling, settled_equal, settled_with_balance, settled_with_refund, overdue_flagged, chasing, reclaim_requested, reclaimed, disputed, rejected, cancelled |
| PAY | draft, submitted, finance_approved, paid, rejected |
| EXP | draft, submitted, dept_approved, ticket_checked, finance_cosigned, paid, rejected, cancelled |

## 13. 审计

关键迁移写 `audit_log`：`entity`, `entity_id`, `from_status`, `to_status`, `actor_id`, `at`, `comment`。SoD 校验失败亦记。
