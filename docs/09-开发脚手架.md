# 09 · 开发脚手架（阶段 1）

> 开工授权：2026-11-06（用户：全部待做）。  
> **同日补充：** 不能嵌进 Canvas / KEMI One 的地方一律在本仓独立做。  
> 阶段 0 已完成。本文件说明本仓里**已经能独立运行**的阶段 1 Web/API。

## 1. 选型怎么落地

| 决定 | 在本仓的做法 |
|------|----------------|
| A 的嵌入边界 | 业务在 `registerAdminProcurement(app, options)` 里。宿主以后可以把自己的 HTTP 服务传进来。现阶段不依赖宿主 |
| 本仓独立运行 | 页面、OIDC 回调、路径①状态机由 `app/src/main.ts` 直接提供。缺宿主能力的部分不在这里等待 |
| KEMI OIDC 网页接入 | 服务端授权码：`/oauth/authorize` → 回调 → `POST /oauth/token` → 需要时 `GET /oauth/userinfo` |
| 身份 ≠ 权限 | `sub` 写入 `uc_user_id`。角色表只在本模块 |
| D erp-pro | `ErpProInboundPort`。默认实现是 stub，不发网络请求，不接收 cookie |
| C 金蝶 | 没有回写代码 |
| 金额 | 环境变量为空就是未配置。缺失时拒绝审批，不套默认金额 |

`app/src/main.ts` 是阶段 1 的独立运行入口，不是 Canvas，也不假装自己在宿主里。

## 2. 技术栈

TypeScript，Node.js 20+。一个进程里同时提供 HTTP API 和一页静态界面。

- HTTP：Fastify。模块以插件形式挂上，可用 `routePrefix` 挂到宿主路径下
- 持久化：进程内内存，方便测试。换库时保持 `ProcurementService` 的行为即可
- 测试：`node:test`，`npm test` 会先做类型检查

没有把 Next.js 拆成第二个包，是为了让「可嵌入的服务端状态机」和页面走同一条边界。

## 4. 本地运行

```bash
cd app
cp .env.example .env
# 编辑 SESSION_SECRET（至少 16 字符）。OIDC 三项有真实 Web 应用后再填。
# 只做界面走查时，把 ALLOW_DEV_LOGIN 设为 true。不要在共享环境开启。
npm install
npm start
```

浏览器打开 `http://127.0.0.1:3000/`。

- **KEMI 登录**：`GET /auth/login` 跳到 UserCenter。回调 `GET /auth/callback` 在服务端换票。`client_secret` 不进浏览器。
- **开发登录**：仅当 `ALLOW_DEV_LOGIN=true`。用种子泳道用户建立会话，不产生第二套密码。
- 新的 OIDC 用户状态是 `pending`、没有角色，直到行政在 `POST /api/users/:id/roles` 授权。

测试：

```bash
npm test
```

仓库根目录的 `npm test` 会转到 `app`。

## 5. 环境变量

见 `app/.env.example`。

| 变量 | 作用 |
|------|------|
| `KEMI_CLIENT_ID` / `KEMI_CLIENT_SECRET` / `KEMI_REDIRECT_URI` | Web 应用凭证。secret 只在服务端换票 |
| `KEMI_UC_API` | 默认 `https://kemi.newlinksz.com/usercenter` |
| `SESSION_SECRET` | 本地会话。不是 KEMI 的 secret |
| `ALLOW_DEV_LOGIN` | 默认 false |
| `THR_CNY_*` / `THR_HKD_*` | 财务加签、总经理、比价、资本化。空着表示占位 |

不使用 `id_token` 和 `refresh_token`。access_token 过期后重新授权。站间免登 `/kemi/sso` 未纳入这期骨架。

## 6. 角色与 SoD

角色：`applicant`、`dept`、`admin`、`finance`、`ceo`、`cashier`。存在角色表，不写回 KEMI。

| 规则 | 拒绝点 |
|------|--------|
| S3 | 部门通过或驳回时，操作者不得是请购申请人 |
| S1 | 直接验收或代收登记时，操作者不得是 PO 下单人。确认人必须是请购申请人 |
| S2 | 出纳付款时，付款人不得是三单匹配人（记账人） |

违反时 HTTP 409，`error=SOD_VIOLATION`，`sodViolationCode` 为 S1/S2/S3，单据状态不变，并写审计。没有管理员绕过开关。

S4 只记录建卡人与保管人，细则仍待定，本期不拦截。S5 属于预付，本期没有预付单据。

## 7. 路径①（阶段 1）

`PR draft → submitted → 部门审批 → 按阈值跳过或经过财务/总经理 → sourcing → ready_for_po → PO issued → awaiting_receipt → 验收 → ①-8a 或 ①-8b → 发票 → 三单匹配 → 付款申请 → 财务批准 → 出纳付款`。

- 低额跳过 ①-3 与 ①-4；中额只跳过 ①-4。审计 `skipped=true`，`skippedReason=below_threshold`。
- 达 `THR_*_RFQ` 必须三家报价且选定一家。未达门槛，或整单都是 `low_value`，必须填免比价原因码。
- D6 只接受 `after_delivery` 与 `monthly`。`prepay` 返回 `PREPAY_NOT_IN_SCOPE`。
- 月结只多一个 `payment_terms_days`，不另开路径。
- D4：行品类为 `fixed_asset`，或金额达到 `THR_*_CAPEX`，走建卡；否则费用化。耗材与低值费用化时调用入库 stub。纯服务不入库。
- 请购提交记软占用，下 PO 记硬占用，部门驳回释放。没有预算模块。
- 三单金额必须相等。没有容差配置，就不发明容差。
- 付款审批只有 ①-12。总经理是否复用请购高额档仍待确认，代码不加这个节点。

生产品类 `production_material`、`outsourced_processing`、`bom_component` 在创建时拒绝，单据不会写入。

## 8. 测试与夹具

`app/test/helpers.ts` 里的数字只注入到当次测试的配置，用来区分低、中、高额和比价、资本化。它们不是公司的金额政策，`loadThresholds({})` 的结果全部是 `null`。

覆盖至少包括：

- `TC-①-2-S3-reject`
- `TC-①-7-S1-reject`
- `TC-①-13-S2-reject`
- `TC-① happy after_delivery`
- 生产品类拒绝、预付拒绝、阈值缺失、OIDC 换票与 `sub` upsert

## 9. 嵌入时宿主要做的事

1. 创建 HTTP 服务，调用 `registerAdminProcurement`。
2. 自己保管 `client_secret` 与会话密钥。
3. 需要换存储时，替换内存仓储，不要从本模块去调宿主的用户表。
4. 真实 erp-pro 上线时实现 `ErpProInboundPort`。请求类型里没有 cookie 字段；会话种类只能是 `admin_inbound`。

本模块不会自动注册到任何名为 Canvas 的宿主上。
