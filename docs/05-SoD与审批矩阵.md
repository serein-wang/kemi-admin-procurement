# 05 · SoD 与审批矩阵

## 1. SoD 规则（忠实源稿）

| 代号 | 规则 | 系统落点建议 |
|------|------|----------------|
| S1 | 下单人 ≠ 验收人 | `PO.issuer_id ≠ GRN.accepter_id`；保存/确认时硬校验 |
| S2 | 记账人 ≠ 付款人 | 付款过账：`voucher.creator_id ≠ payment.payer_id`（①-13 / ②-8） |
| S3 | 申请人 ≠ 部门审批人（禁自批） | 所有部门审批节点：`applicant_id ≠ dept_approver_id` |
| S4 | 固资建卡与保管职责分离 | `AssetCard.creator_id ≠ custodian_id`。建卡与之后的调拨都硬校验。违反则 409，`sodViolationCode=S4`，不改卡、不改采购单处置。无管理员绕过（阶段 4 落定；源稿曾标细则待定） |
| S5 | 预付申请人 ≠ 预付审批人 ≠ 预付付款人 | `PREPAY.applicant_id ≠ payment_approver_id ≠ payer_id` |

违反 SoD：拒绝状态迁移，记录 `sod_violation_code`，不提供管理员一键绕过（若需紧急例外，另开「例外审批单」——**建议，待 Rock 确认，非源稿原文**）。

## 2. 审批矩阵骨架（金额阈值全部 TBD）

源稿表格结构如下；数值用占位符，**禁止写入臆造金额**。

### 2.1 占位符命名

| 占位符 | 含义 |
|--------|------|
| `THR_CNY_FIN` | 请购：达此额需财务加签（中额下沿） |
| `THR_CNY_CEO` | 请购：达此额需总经理（高额下沿） |
| `THR_HKD_FIN` / `THR_HKD_CEO` | 港币平行 |
| `THR_CNY_RFQ` / `THR_HKD_RFQ` | 三家比价门槛 D3 |
| `THR_CNY_CAPEX` / `THR_HKD_CAPEX` | 固资资本化 D4 |
| `THR_CNY_PREPAY_FIN` / `_CEO` | 预付加签/总经理 |
| `THR_HKD_PREPAY_FIN` / `_CEO` | 预付港币 |
| `PREPAY_RATIO_MAX` | 预付占 PO 比例上限 |
| `THR_CNY_REIM` / `THR_HKD_REIM` | 报销超额加签（D5） |
| `PREPAY_OVERDUE_DAYS` | ①-E1 超期天数 |

低额：< `THR_*_FIN`；中额：`THR_*_FIN` ≤ x &lt; `THR_*_CEO`；高额：≥ `THR_*_CEO`。

### 2.2 路径① 请购

| 场景 | 部门负责人 | 财务负责人 | 总经理 | 路径摘要 |
|------|------------|------------|--------|----------|
| 低额 | 必审 | — | — | ①-2 → 跳过 ①-3/①-4 |
| 中额 | 必审 | 必签 | — | ①-2 → ①-3 → 跳过 ①-4 |
| 高额 | 必审 | 必签 | 必审 | ①-2 → ①-3 → ①-4 |

### 2.3 比价 / 货到付款

| 场景 | 说明 |

| 比价 | D3 / ①-5；门槛 `THR_*_RFQ` |
| 货到付款 | ①-11 → ①-12（财务）→ ①-13；总经理「视矩阵」（源稿原文；是否复用请购高额档 **待确认**） |

### 2.4 路径① 预付

| 场景 | 部门 | 财务 | 总经理 | 摘要 |
