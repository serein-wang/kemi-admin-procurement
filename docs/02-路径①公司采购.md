# 02 · 路径① 公司采购（主流程）

> 对齐源稿：阶段 A 申请与审批 · 阶段 B 下单与付款条件 · 阶段 C 货到付款。  
> 先款后货自 D6 转入 `docs/03`。

## 1. 例子（货到付款）

申请人提交「会议室显示器 ×2」请购 → 部门负责人批准 → 金额未达财务阈，跳过①-3/①-4 → 达比价门槛，行政询 3 家并选定 → 下行政 PO（货到付款）→ 申请人收货验收 → 判定非固资走费用化 → 财务登记发票并三单匹配 → 行政发起付款 → 财务批付款 → 出纳支付。

## 3. 状态机建议（请购 → PO → 收货 → 付款）

### 3.1 请购单 `PR`（Purchase Requisition）

```
draft → submitted → dept_approved → [finance_approved?] → [ceo_approved?]
  → sourcing          # 待比价或已免比价
  → ready_for_po
  → closed_converted  # 已转 PO
  → rejected | cancelled
```

说明：`finance_approved` / `ceo_approved` 为可跳过节点；跳过时写入 `skipped_reason=below_threshold`。

### 3.2 行政采购单 `PO`

```
draft → issued → awaiting_receipt
  → partially_received → fully_received
  → matched            # 三单匹配通过（货到付款路径）
  → payment_pending → paid → closed
  → cancelled
```

若 D6=先款后货：`issued` 后进入 `awaiting_prepay`（见 docs/03），到货后再汇入 `awaiting_receipt`。

### 3.3 收货单 `GRN`

```
draft → confirmed → (linked asset or expense posted)
```

确认人必须满足 S1（≠ PO.issuer_id）；代收策略见 Q6。

### 3.4 付款申请 `PAY`

```
draft → submitted → finance_approved → paid | rejected
```

## 4. 判断节点实现要点

| 节点 | 输入 | 动作 |
|------|------|------|
| D1/D2 | PR 本币金额 vs `THR_*` | 路由加签/总经理或跳过 |
| D3 | 金额 vs `THR_*_RFQ` | 强制①-5 或 `rfq_waived` |
| D6 | PO.`payment_terms` | `after_delivery` / `monthly` / `prepay` |
| D4 | 金额 vs `THR_*_CAPEX` 或品类强制 | ①-8a vs ①-8b |

## 5. 不做的事

- 不在主流程插入源稿没有的审批人
- 不把月结做成独立路径（与货到付款同属 D6 非预付分支；账期字段 `payment_terms_days` 区分）
