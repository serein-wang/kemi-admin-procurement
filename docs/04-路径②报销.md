# 04 · 路径② 员工垫付报销

> 源稿 v3 泳道曾将事前画为虚线可选；**Q5 已于 2026-11-06 改写确认：一律强制事前申请与部门审批**（本页以确认结论为准）。

## 1. 例子

员工先提交事前申请 → 部门负责人批准 → 再垫付购买办公耗材 → 提交报销单+发票（关联事前单）→ 部门批准 → 会计审票通过 → 未超限额跳过加签 → 出纳打款至员工账户。

## 3. 状态机建议

### 3.1 事前申请单 `PRE`（强制）

```
draft → submitted → approved → (consumed_by_expense)
  → rejected | cancelled | expired
```

### 3.2 报销单 `EXP`

```
draft → submitted → dept_approved → ticket_checked
  → [finance_cosign?] → payment_approved → paid
  → rejected | cancelled
```

硬规则：`EXP.pre_approval_id` 必填且指向 `PRE.status=approved`；否则拒绝 ②-4 提交。`require_pre_approval` 固定为 true。

## 4. 与路径①边界

- 路径②无行政 PO、无比价、无三单匹配（以票+报销单为主）
- 同一笔消费不得同时以路径①付款与路径②报销（建议查重：发票号/金额/日期）——**建议，待财务确认**（非原开放问题列表条目）
