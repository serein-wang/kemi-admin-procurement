# 03 · 路径① 预付与例外

> 自 D6「先款后货」进入。步骤 ①-P* / ①-E*。到货后复用 ①-7 / ①-9 / ①-10。  
> v3 相对 v2 的核心增量。

## 1. 例子（部分预付）

行政对已签发 PO 提预付申请（附 PO + 形式发票）→ 部门批 → 达财务阈加签 → 未达总经理阈跳过 → 财务批预付 → 出纳付预付 → 会计记预付账款 → 等待到货 → 申请人验收 → 登记正式发票 → 三单匹配（含预付核对）→ 核销预付 → 预付<票额 → 走①-11~13 付尾款。

## 4. 状态机建议 · 预付单 `PREPAY`

```
draft → submitted → dept_approved → [finance_cosign?] → [ceo_approved?]
  → finance_payment_approved → paid → accrued      # ①-P7 已挂账
  → awaiting_delivery
  → (GRN confirmed + invoice + match)
  → settling → settled_equal | settled_with_balance | settled_with_refund
  → overdue_flagged → chasing → reclaim_requested → reclaimed | disputed
  → rejected | cancelled
```

S5 静态校验：`applicant_id ≠ payment_approver_id ≠ payer_id`。

## 5. D-P2 分支

| 结果 | 动作 |
|------|------|
| 预付 = 票额 | ①-P8 完成；PO 可关闭（无尾款） |
| 预付 < 票额 | ①-P9 → 复用 ①-11~①-13 |
| 预付 > 票额 | ①-P10 退款或挂账 |

## 6. 与主流程衔接规则（建议）

- 预付申请必须关联已签发 `PO`（①-P1）
- 未完成预付支付前，货到付款路径的 ①-11 不应并行付全款（防重复付）——**建议，待财务确认**
- 形式发票可启预付；核销以正式票为准（Q13）

## 7. 已确认附件与溢付（Q12 / Q14）

- **Q12：** 预付必附 PO，并附合同或形式发票之一；达 `THR_*_PREPAY_CONTRACT` 强制合同。
- **Q14：** 溢付默认退款申请（行政→财务→出纳）；挂账须财务负责人批准+原因码。
- **Q11：** `PREPAY_OVERDUE_DAYS` + 每日已付未验收超期清单。
